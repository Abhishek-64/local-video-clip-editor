# Functional Specification & Requirements Analysis

---

# 1. Identify the Application

### What the Application Is
The application is a **Privacy-First Local Video Clip Editor & Multi-Platform Publishing Studio**. It allows creators to take long-form or raw video files, edit, crop, split, trim, brand, and enhance them directly inside their web browser, and then either export the finished clips locally or schedule and publish them automatically to social media platforms (YouTube Shorts and Facebook Reels).

### What Problem It Solves
1. **Privacy & Bandwidth Constraints:** Traditional online video editors require uploading massive multi-gigabyte source video files to cloud servers before editing can even begin. This application performs video decoding, frame extraction, visual transformations, audio mixing, and encoding locally on the user's computer with zero video data uploaded for editing.
2. **Repurposing Bottlenecks:** Content creators often need to slice long horizontal videos (e.g., movies, podcasts, gaming streams, interviews) into dozens of short, mobile-optimized vertical clips (9:16 format) with consistent branding, titles, part numbering, and hashtags. Doing this manually in traditional timeline software is repetitive and slow.
3. **Multi-Platform Distribution Overhead:** Creators waste significant time manually uploading individual clips one-by-one to YouTube and Facebook, configuring titles, tags, descriptions, and scheduling times. The application automates batch generation, metadata templating, and scheduled publishing across platforms.

### Who It Is Intended For
* **Social Media Content Creators & Clip Channels:** Channels that curate movie clips, anime highlights, podcasts, comedy moments, and gaming highlights for YouTube Shorts, Instagram Reels, TikTok, and Facebook Reels.
* **Podcasters & Streamers:** Creators wanting fast vertical clipping of highlights with speaker tracking and branded overlays.
* **Privacy-Conscious Video Editors:** Users who want to edit videos locally on their own hardware without cloud upload dependencies.

### Main Purpose of the Application
To provide a fast, browser-based workspace for slicing, enhancing, branding, and distributing video clips into single or sequential multi-part short-form content across social video platforms with automated scheduling.

### Primary User Workflow
1. **Import:** User selects a local video file (MP4, MOV, WebM, MKV, AVI). The application inspects video resolution, framerate, and audio tracks locally.
2. **Configure Master Metadata:** User enters the project or movie title, chooses a part numbering format (e.g., `{movie} - Part {part}`), and picks global hashtags.
3. **Framing & Slicing:**
   * User chooses a target aspect ratio (e.g., 9:16 vertical, 1:1 square, 16:9 horizontal, or custom freeform crop).
   * User enables optional Smart AI Face Tracking or adjusts background styling (blurred video, custom image, or solid color).
   * User splits the video into parts (via playhead split, duration intervals, part counts, or custom range points) and marks unwanted sections as "Cut" (excluded).
4. **Branding & Audio Enhancement:** User adds dynamic text overlays, logo watermarks, color filters/fades, voiceover tracks with smart ducking, and background music.
5. **Apply or Save Presets:** User can apply 1-click studio presets (saved combinations of overlays, logos, YouTube templates, and Facebook defaults) or save the current setup as a new preset.
6. **Batch Queue & Render:** User queues single parts, merged cleaned video, or batch sequential clips. The in-browser export engine renders the clips to MP4 or WebM.
7. **Export & Publish:**
   * **Local Download:** User previews rendered clips and downloads individual files or all clips bundled in a ZIP archive.
   * **Social Publishing:** User schedules or publishes clips directly to **YouTube Shorts** and/or **Facebook Reels** with automated release intervals (e.g., every 1 hour, every 2 hours, peak viral hours, or custom schedules).

# 2. Complete Feature Inventory

### Feature: Local Video Import & Metadata Detection
* **What the user can do:** Select a video from their local device via drag-and-drop or file browser; replace or change the selected video at any time.
* **What it accomplishes:** Loads the video into the browser playback and editing engine without uploading the raw video to any server.
* **Important user options/settings:** Accepts `.mp4`, `.mov`, `.webm`, `.mkv`, `.avi` video formats.
* **Expected result/output:** Displays video preview, duration, dimensions, auto-detected resolution profile (e.g., 1080p, 4K), detected framerate (FPS), and audio profile (channel count and sample rate). Automatically initializes project title from the cleaned video filename.
* **Restrictions/conditions:** Corrupted or browser-unsupported video container formats trigger an error notification.

### Feature: Universal Master Sync Hub
* **What the user can do:** Define a master title, master part naming template, and master hashtag pool that synchronize simultaneously across all editor tools (Canvas text overlay, YouTube metadata, Facebook captions, and batch file naming). Toggle live auto-sync on/off, or manually force synchronization.
* **What it accomplishes:** Eliminates redundant data entry by ensuring title, part formatting, and hashtags match everywhere.
* **Important user options/settings:**
  * Master Title input with "Auto-Clean from File" option (strips file tags, resolutions, and extensions).
  * Part Naming Style presets (`{movie} - Part {part}`, `{movie} - Pt. {part}`, `{movie} - Ep. {part} Pt. {part}`, `{movie} [Part {part}]`, `{movie} #{part}`).
  * Universal Hashtag pool with 1-click hashtag packs (All-In-One, Cinema/Movie, Anime, Gaming, Podcast).
  * Auto-Sync Toggle (Live ON / Manual OFF) and "Sync All" button.
* **Expected result/output:** Updating master title or template automatically propagates to the video canvas preview, clip naming tables, YouTube title/description templates, and Facebook Reels captions.

### Feature: Precision Timeline & Manual Split/Cut Slicing
* **What the user can do:**
  * Scrub playback through the entire video with live timestamp indicators.
  * Adjust global start and end trim boundaries.
  * Split the video into multiple segments at the exact playhead position (via UI button or global `S` keyboard shortcut).
  * Split video into equal segments by duration (e.g., 60 seconds per clip) or by part count (e.g., split into 4 equal parts).
  * Toggle individual segments between **KEPT** and **CUT (Deleted)** states.
  * Adjust individual segment start and end timestamps (nudge by ±1s or snap to current playhead).
  * Rename individual segment titles.
  * Drag segment boundary handles directly on the timeline with magnetic snapping (within 0.35s of adjacent boundaries).
* **What it accomplishes:** Allows users to cut out silence, filler, or unwanted scenes, and structure continuous or sequential multi-part clips.
* **Important user options/settings:** Duration mode vs Part count mode; Preserve Cuts toggle (when re-splitting, keeps cut sections excluded); Auto-skip cut sections during preview playback.
* **Expected result/output:** Sequential list of active parts automatically re-numbered starting from Part 1. Preview player automatically skips cut sections during playback if enabled.

### Feature: Interactive Framing & Multi-Platform Aspect Ratio Crop
* **What the user can do:**
  * Select target video format / aspect ratio:
    * `9:16` (Instagram Reels, YouTube Shorts, TikTok — 1080×1920)
    * `16:9` (YouTube Standard Landscape — 1920×1080)

    * `4:5` (Portrait Feed — 1080×1350)

  * In `9:16` mode, switch between **Fit (Full horizontal video with top/bottom backdrop)** and **Fill (Zoom to fill vertical screen with side cropping)**.
  * Adjust Horizontal (X) pan, Vertical (Y) pan, and Zoom scale (0.8x to 3.0x).
  * Use snap alignment shortcuts (Center, Left, Right, Top, Bottom, Full Frame).
  * Directly drag and resize the crop bounding box on the video preview screen.
* **What it accomplishes:** Adapts horizontal widescreen video to vertical mobile or custom formats without distortion.

* **Important user options/settings:** On/Off toggle.
* **Expected result/output:** The vertical crop window dynamically follows the primary face with exponential moving average (EMA) smoothing to eliminate jitter. Runs 100% locally in the browser without external AI APIs.

# 4. Complete User Workflow

### Workflow 1: Single Clip Quick Edit & Local Download
1. User opens the application and drops a video file into the dropzone.
2. Application auto-detects video properties and populates the workspace.
3. User selects the desired framing (e.g., 9:16 vertical fit with blurred backdrop).
4. User positions the playhead on the timeline and sets Start and End trim points.
5. User customizes the on-screen title text and adds a brand logo.
6. User clicks "Generate Clip" in the Processing Queue.
7. Application renders the clip in the browser.
8. User previews the clip in the modal player and clicks "Download" to save the MP4.

---

### Workflow 2: Slicing Long Video into Sequential Parts & Batch Export
1. User loads a long video file (e.g., a 20-minute video).
2. User enters Master Title (e.g., `Top 10 Moments`) and selects part template `{movie} - Part {part}`.
3. User navigates to the **Split & Cut** tab.
4. User selects "Split into 60s Chunks" or manually scrubs to key timestamps and presses `S` to split at playhead.
5. User reviews the generated parts table, marking uninteresting segments as "Cut" (excluded). Active parts automatically renumber sequentially (Part 01, Part 02, Part 03...).
6. User clicks "Generate All ([N] Clips)" in the Processing Queue.
7. The browser renders each clip sequentially in the background while updating progress bars.
8. In the Generated Clips library, user clicks "Download All ZIP" to download a single zip archive containing all numbered MP4 clips.

---

### Workflow 3: Non-Contiguous Video Cleaning (Cut & Merge)
1. User imports a raw video with bad takes, pauses, or filler sections.
2. User plays the video and splits around unwanted sections, marking those sections as "Cut".
3. User checks the remaining kept segments in the Split & Cut table.
4. User clicks **"Merge All Kept Parts into 1 Video"**.
5. Application exports a single continuous video with all cut sections seamlessly removed.

---

### Workflow 4: Studio Preset Creation & Application
1. User designs a complete channel branding style: 9:16 vertical crop, blurred background at 40% blur, Impact font title text with yellow outline, top-right logo, cinematic color filter, and specific YouTube upload defaults.
2. User clicks "+ Save Preset" in the Universal Master Hub.
3. User names the preset `Cinematic Shorts`, selects category `Movies`, and saves.
4. On future sessions with different video files, user selects `Cinematic Shorts` from the preset dropdown to re-apply the entire visual, branding, and metadata configuration in one click.

---

### Workflow 5: Automated YouTube Shorts Scheduled Series Pipeline
1. User signs in and connects their YouTube channel via Google OAuth.
2. In the YouTube tab, user selects **"Automated Schedule Pipeline"**.
3. User sets starting release time (e.g., Tomorrow at 6:00 PM) and interval (e.g., `Every 2 Hours`).
4. User verifies the calculated timetable preview (Part 1 at 6 PM, Part 2 at 8 PM, Part 3 at 10 PM...).
5. User clicks "Generate All Clips".
6. As each clip finishes in-browser rendering, the upload engine automatically creates a YouTube upload session, transfers video bytes directly to YouTube, sets visibility to private, and assigns the scheduled release timestamp.
7. User monitors live upload progress and views scheduled confirmation links in the YouTube History log.

---

### Workflow 6: Facebook Reels Batch Scheduling via Cloud Bridge
1. User connects their Facebook Page via Meta OAuth.
2. User renders clips in the editor.
3. In the Facebook tab or Multi-Schedule modal, user selects all completed clips, chooses **Peak Viral Hours** scheduling, and enters captions and hashtags.
4. User submits the batch.
5. For each clip, the application uploads the video temporarily to Backblaze B2 storage, generates a signed HTTPS ingestion link, and registers the scheduled Reel with the Meta Graph API.
6. The background cron worker verifies publication at the scheduled time and automatically purges the temporary B2 storage file.

---

### Workflow 7: Simultaneous Multi-Platform Batch Scheduling
1. User has both YouTube channel and Facebook Page connected.
2. User renders a batch of 5 clips.
3. User clicks **"⚡ Multi-Schedule"** in the Generated Clips library.
4. User checks both "YouTube Shorts" and "Facebook Reels".
5. User chooses starting time and interval.
6. User clicks "Dual-Schedule 5 Clips".
7. All 5 clips are queued, uploaded, and scheduled on both YouTube and Facebook in a single automated process.

# 10. Processing & Outputs

```
┌─────────────────┐       ┌──────────────────────────────┐       ┌────────────────────────┐
│  Input Video    │ ────> │  In-Browser Export Engine    │ ────> │  Completed Outputs     │
│  (MP4/MOV/WebM) │       │  (WebCodecs H.264 / WebGL)   │       │  (MP4 / WebM / ZIP)    │
└─────────────────┘       └──────────────────────────────┘       └───────────┬────────────┘
                                                                             │
                                              ┌──────────────────────────────┴──────────────────────────────┐
                                              ▼                                                             ▼
                               ┌─────────────────────────────┐                               ┌─────────────────────────────┐
                               │  YouTube Shorts Pipeline    │                               │  Facebook Reels Pipeline    │
                               │  (Direct Resumable Upload)  │                               │  (B2 Staging + Graph API)   │
                               └─────────────────────────────┘                               └─────────────────────────────┘
```

### Processing Execution
1. **Input:** Local video file, audio tracks (voiceover, background music), image assets (logo, background picture), and configured timeline split segments.
2. **User Action:** Clicks "Generate All", "Generate First N", "Generate Range", "Export Merged Cleaned", or "Export Single Part".
3. **Processing Steps (Client-Side):**
   * Initializes target canvas at specified resolution (e.g., 1080×1920).
   * Spawns WebCodecs hardware `VideoEncoder` (H.264) with configured bitrate and framerate (or falls back to MediaRecorder stream capture).
   * Mixes audio tracks offline (original audio + voiceover ducking + background music).
   * Seeks through video frames, rendering backdrop, cropped video, color grading filters, text overlays, and logo watermarks onto each frame.
   * Feeds rendered frames to encoder.
   * Bundles encoded video and audio into fast-start ISOBMFF MP4 container.
4. **Outputs:**
   * In-memory video Blob and playable object URL.
   * Downloadable MP4 or WebM video file.
   * Packaged multi-clip ZIP archive.
5. **Publishing / Cloud Outputs:**
   * Direct-to-YouTube video record with assigned video ID and scheduled release date.
   * Staged B2 video record + Meta Graph API Reel submission with permalink.
6. **Error / Retry Handling:**
   * Individual failed jobs flag an error status badge without stopping the rest of the batch queue.
   * Single-click retry action available for failed rendering or failed social uploads.

# 12. Permissions & Restrictions

* **Anonymous vs Authenticated:** Anonymous users have full access to local editing, rendering, and downloading. Cloud sync of presets and cross-device social tokens requires account login.
* **Browser Capabilities:**
  * Hardware acceleration and WebCodecs require a modern Chromium-based browser (Chrome, Edge, Brave, Opera) or compatible browser for maximum export speed.
  * If WebCodecs is unsupported, system automatically falls back to standard MediaRecorder stream capture.
* **File Constraints:**
  * Supported video containers: MP4, MOV, WebM, MKV, AVI.
  * Supported audio: MP3, WAV, AAC, M4A, OGG.
  * Supported images: PNG, JPG, WebP.
* **Platform Publishing Restrictions:**
  * YouTube Shorts: Videos must be 60 seconds or less and vertical/square to be categorized as Shorts. Scheduled dates must be in the future.
  * Facebook Reels: Maximum duration 90 seconds (recommended 60s); vertical 9:16 aspect ratio recommended; requires connected Facebook Page.
  * Backblaze B2 files: Automatically purged after Reel submission; maximum temporary storage duration 7 days.

* **Social Publishing:** Requires active OAuth authentication and appropriate permissions on target channels/pages.

### M. User Workflows
1. **Single Clip Quick Edit:** Import → Crop/Frame → Trim → Brand → Render → Download.
2. **Multi-Part Series Batching:** Import → Master Title & Template → Split/Cut → Brand/Enhance → Batch Queue → Download ZIP.
3. **Cleaned Video Export:** Import → Split unwanted sections → Mark as Cut → Merge Kept Parts → Download Continuous Video.
4. **Automated YouTube Series Schedule:** Import → Slicing → Set YouTube Schedule Pipeline & Interval → Batch Render & Auto-Upload.
5. **Facebook Reels Scheduling:** Import → Slicing → Select Clips → Choose Peak Hours & Thumbnail Frames → Staged Cloud Bridge Submission.
6. **Dual-Platform Multi-Scheduling:** Render Clips → Open Multi-Schedule Modal → Check YouTube + Facebook → Select Interval → One-Click Dual Schedule.

### N. Functional Dependencies
* Video slicing, framing, branding, and export require an imported video file.
* Multi-part numbering requires an active segment sequence.
* Merged video export requires at least one kept video segment.
* YouTube publishing requires an active Google OAuth connection.
* Facebook Reels publishing requires an active Meta OAuth connection, connected Page, and Backblaze B2 storage bridge.
* Multi-platform dual-scheduling requires at least one connected social account.
* Cloud preset synchronization requires user authentication.
